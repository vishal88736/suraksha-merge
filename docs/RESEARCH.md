# Research workflow and evidence boundary

Suraksha-Merge tests whether independently trained schema and response specialists retain their strengths after weighted-delta merging. It does not assume that merging eliminates task interference. The live desk currently executes the shared TypeScript rule engine and reply templates.

## Environment

The web application requires Node 22.18+; CI uses Node 24. Offline curation and regression checks use Python 3.12+ and the Node engine, with no model dependencies. Toolkit snapshots are pinned in `research/toolkit_revisions.json`. Optional environments are split to avoid installing GPU libraries just to run the desk:

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements-audit.txt
# Optional enhanced data hygiene; also install a compatible Presidio spaCy model.
uv pip install --python .venv/bin/python -r requirements-curation.txt
# On a compatible CUDA training machine, in a separate environment:
uv venv --python 3.12 .venv-training
uv pip install --python .venv-training/bin/python -r requirements-training.txt
```

CuratorKIT and AuditKIT have source-available licences. Their pinned repositories contain the applicable terms. AlignTune's dependencies and bundled components retain their own licences.

## Phase 1: curation

```bash
python3 phase1_curatorkit_pipeline.py --demo
.venv/bin/python phase1_curatorkit_pipeline.py --demo --use-curatorkit --output data/generated-curatorkit
# Enable actual Presidio after configuring its NLP model:
.venv/bin/python phase1_curatorkit_pipeline.py --input /path/to/authorised.jsonl --presidio
```

The bundled 18 synthetic seeds are **bootstrap fixtures**, not a production training set. Gold fields are hand-specified synthetic expectations; customer drafts are generated by rules and require independent regional-language review. Ten cases are in train, three in validation and five in test. Scenario families are isolated, including coercion, missing evidence, conflicting references and the future-policy boundary. Keep all paraphrases, repaired responses and SMS templates of a family in the same split.

The local pipeline validates the complete schema, checks numeric evidence against the message, masks identities in messages and candidate replies, deduplicates exact normalized messages, and produces same-task DPO pairs. Unsupported references, duplicate IDs and family leakage fail closed. A recovery record explicitly says when a rule template replaced an unsafe candidate. It is not labelled an LLM RewardRefiner run. The default scrubber is contextual regex; `--presidio` runs the real Presidio analyzer/anonymizer after that pass and protects only context-labelled UTR anchors. No blanket 12-digit allowlist is used.

`--use-curatorkit` calls the actual `Curator(CuratorConfig(...)).run()` API to normalize and deduplicate masked candidates before the existing local gates. Actual toolkit survivors feed the exports. A final schema/Alpaca pass validates SFT training records and the real DPO exporter handles preference pairs. It does not imply that a semantic HallucinationGate, LLM judge, synthetic-generation provider or adaptive LLM recovery ran. Those require a configured generator/judge and independent review. No live provider was called during implementation.

Outputs under ignored `data/generated*/` include per-split `rlvr.jsonl`, `dpo.jsonl`, `sft.jsonl`, `uncurated_sft.jsonl`, `benchmark.jsonl`, rejection/recovery logs, checksums and a dataset card. The uncurated SFT control still masks PII and uses the same split; it intentionally includes labelled unsafe synthetic responses. Use authorised data and mark `human_reviewed` only after actual review.

### Acquired public sources

The [public-data runbook](DATA_CURATION.md) documents the executed acquisition/curation run: five inspected sources, 36,868 downloaded rows, 934 accepted unreviewed UPI cases and 11,655 separately reserved external benchmark records. Install `requirements-public-data.txt` for this CPU-only workflow; run `scripts/prepare_public_data.py --stage all` and `scripts/validate_prepared_data.py`. No NLP model, trainer or model benchmark runs as part of those commands.

Outputs use ignored `data/raw/`, `data/processed/upi-v1/` and `data/benchmarks_external/upi-v1/`. New public silver labels and authored synthetic targets are not engine-verified ground truth. For later approved training, select this corpus explicitly with `--data data/processed/upi-v1`; the existing default review guard stays active. Default training and inference commands below still use the bundled seed output at `data/generated` unless a dataset path is supplied.

## Phase 2: train and merge

```bash
python3 phase2_aligntune_train_and_merge.py --stage plan
# Run the following on the GPU machine after curation and human review:
.venv-training/bin/python phase2_aligntune_train_and_merge.py --stage schema
.venv-training/bin/python phase2_aligntune_train_and_merge.py --stage empathy
.venv-training/bin/python phase2_aligntune_train_and_merge.py --stage curated-sft
.venv-training/bin/python phase2_aligntune_train_and_merge.py --stage uncurated-sft
.venv-training/bin/python phase2_aligntune_train_and_merge.py --stage merge --schema-weight 0.55
```

For an intentionally small synthetic smoke run, follow [the review and training preparation runbook](HUMAN_REVIEW_AND_TRAINING.md). The override now requires a dedicated two-case fixture dataset, `--allow-bootstrap-data --smoke-test --max-steps 1`, and isolated artifact output. A smoke run is not a trained product. `--allow-cpu` is an explicit override for small experiments, never an automatic fallback for a full 3B training run. The current machine's NVIDIA driver is unavailable, so GPU training has not been executed.

The supported AlignTune backend factory uses `dataset_name`, `algorithm="drgrpo"`, flattened LoRA parameters and `create_rl_trainer(..., algorithm="dpo")`. The implementation uses the registry's actual custom-reward factory contract, not the proposal's illustrative decorator. Schema reward requires a reference and scores all fields. Malformed JSON, duplicate keys, extra fields, non-finite values and incorrect critical fields cannot earn a high score.

Tokenizer extension is optional. The default keeps the base vocabulary unchanged. `--stage adapt-tokenizer` obtains script candidates through AlignTune, adds them to a real Hugging Face tokenizer and adapts new input/output embedding rows on the training corpus. It saves one shared base for both specialists. Train **both** adapters with `--shared-base checkpoints/shared-indic-base` after that operation; never give separate random embedding expansions to each adapter. Use a representative, reviewed Indic corpus; the tiny bootstrap set is insufficient to establish language quality. Measure fertility and held-out language quality before adopting the expansion.

Adapter manifests record immutable base identity, vocabulary identity, LoRA targets and dataset identity. Merge verifies compatibility. PEFT concatenation composes the exact weighted sum of low-rank updates; averaging the A/B factors directly would add cross terms. AlignTune's `PEFTMerger` then bakes the active merged update into a full model. Adapters carry checksums for their configuration and safetensors weights; tampered or unverified artifacts are rejected. Checkpoint-only saves are resolved through their manifest, including after a project move. The UI slider exports weights; it does not change a running model. Select weights on validation data before evaluating the frozen test set.

## Phase 3: actual inference and evaluation

Inference uses **two task-prefixed calls to the same checkpoint**: extraction, then reply generation using that extraction as untrusted draft context. All six checkpoints use the same prompts, decoding settings and token limits. The held-out reply prompt contains no gold triage context. Both calls count towards measured latency, token usage and cost.

```bash
.venv-training/bin/python scripts/generate_predictions.py \
  --model Qwen/Qwen2.5-3B-Instruct --output artifacts/base.jsonl
.venv-training/bin/python scripts/generate_predictions.py \
  --model checkpoints/suraksha-merged --output artifacts/suraksha-merged.jsonl
# Repeat for the four remaining checkpoints; unmerged specialists use --adapter.
.venv/bin/python phase3_auditkit_eval.py --auditkit \
  --predictions base=artifacts/base.jsonl \
  --predictions uncurated-sft=artifacts/uncurated-sft.jsonl \
  --predictions curated-sft=artifacts/curated-sft.jsonl \
  --predictions schema=artifacts/schema.jsonl \
  --predictions empathy=artifacts/empathy.jsonl \
  --predictions suraksha-merged=artifacts/suraksha-merged.jsonl
```

Generated outputs are not repaired before scoring. The baseline defaults to the exact `base` label; an absent requested label is an error. Recorded model outputs must have a matching inference manifest; `--allow-unverified-predictions` is an explicit import mode without verified provenance. Prediction IDs must exactly match the benchmark; missing or duplicated cases raise an error. Metrics include the complete schema, every extracted field, exact critical fields, guarantee patterns and required fraud-reporting rails. Optional SacreBLEU computes ChrF as character overlap. Human empathy is separately unmeasured. Pattern checks are conservative heuristics and can produce both false positives and false negatives; neither they nor ChrF certify compliance.

Comparisons use paired bootstrap resampling by scenario family, with a fixed seed. The five-case synthetic test set only verifies mechanics. It cannot establish generalization, causal benefits from merging, language quality, live field performance or statistical superiority. Costs remain null without measured hardware/pricing; no $0.04-per-1K estimate is published as fact.

Verify evaluation plumbing without a model:

```bash
.venv/bin/python scripts/verify_research.py --auditkit
```

This creates explicitly labelled valid/unsafe **fixtures**, executes actual AuditKIT custom scorers, and writes `SCORER_FIXTURE_VERIFICATION`. It must never be presented as a model benchmark.

## Before a model-backed release

Collect a consented, independently annotated corpus; review each regional language; freeze a substantial held-out test set; run all six checkpoints and adversarial families; evaluate semantic guarantees and over-refusal with blinded human review; measure latency and cost on named hardware; and approve the bank-specific reason-code mapping and applicable policy version. A working demo, successful tests and source-checked training commands do not substitute for those measurements.

## Artifact integrity

Remote base configuration, tokenizer and weights are loaded from the same resolved immutable Hugging Face revision. `--revision` can select the desired revision before resolution. Local bases are fingerprinted from weight bytes and vocabulary, so moving a checkpoint directory does not change its identity. Specialist manifests record adapter configuration and weight hashes; merge and inference reject modified or mismatched artifacts and resolve checkpoint-only saves explicitly.

Recorded inference produces a matching manifest with benchmark and prediction hashes. Evaluation requires that manifest by default. `--allow-unverified-predictions` is an explicit inspection escape hatch and cannot establish model-quality claims. Reordering prediction flags does not change the named `base` comparison. Empty or modified curated datasets are rejected before training.

Human annotation decisions, held-out evaluation preparation, CPU token measurements, environment checks and safe smoke commands are documented in [HUMAN_REVIEW_AND_TRAINING.md](HUMAN_REVIEW_AND_TRAINING.md). Actual review and GPU trainer execution remain external dependencies.
